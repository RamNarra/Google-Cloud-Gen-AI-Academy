1. What Exactly is an AI Agent?

We use ChatGPT every day (which is just a conversational interface). An AI Agent is different. It doesn't just talk; it plans, reasons, and executes tasks for you.

To do this, it requires four absolute core components:

  1. Model: This is the brain (e.g., Gemini, OpenAI, Claude). It reasons over the user's goals, creates a plan, and generates text.
  2. Tools: These are the "hands" of the agent. Models can't access live data. Tools (like a Weather API, Calendar API, or Flight Scraper) go out to the real world, fetch data, or perform actions, and give the data back to the model.
  3. Orchestration: The manager. It handles when to call the model, which tools are available, handling input/output parameters, and maintaining memory/state. It decides what to do based on what the tools return.
  4. Runtime: The execution environment where all this logic actually runs (e.g., a Python runtime, a container, or a serverless function).
Real-World Example: Leave Balance Checker

User: "How many vacation leaves do I have?"
Orchestrator: Calls Model.
Model: Realizes it needs context. Tells Orchestrator to use Calendar Tool & Policy Tool.
Tools: Calendar Tool finds out you took 5 days off. Policy Tool finds total allowed is 25.
Orchestrator: Feeds these answers back to the Model.
Model (Reasoning): "Okay, they took 5 days. Policy says 25. But wait, Calendar says 1 day was marked 'Out of Office' but outside business hours, so it wasn't a leave."
Model Output: "You have 21 days of vacation leaves pending."

2. Enter ADK (Agent Development Kit)

Google noticed everyone was building agents completely differently, making code hard to maintain. ADK was built to standardize and democratize this process—making agent development feel exactly like normal software development.

Core Characteristics of ADK

1. Model Agnostic: You aren't forced to use Gemini. You can plug in any open-source or proprietary model. The agent is the product, the model is easily swappable.

2. Deployment Agnostic: It's just Python code. Run it locally, in a Docker container, in a VM, or on Vertex AI.

3. Interoperability: Easily connect to your own existing memory systems or third-party libraries.

The 5 Levels of AI Abstraction

ADK aims to hit the perfect sweet spot for developers. Here is where it sits in the hierarchy:

  • Level 0 (DIY): Hardcore ML engineer building everything from scratch. Huge dev time, hard to maintain.
  • Level 1 (Low-Level LLM Frameworks): e.g., standard LangChain. Just wraps the model call to make talking to models easy.
  • Level 2 (Low-Level Orchestration): e.g., LangGraph. Manages multiple components talking to each other but lacks high-level agentic patterns out-of-the-box.
  • Level 3 (Agent Frameworks): This is ADK. Complete frameworks handling state, memory, sessions, and tool interfaces. Includes OpenAI Agents SDK as a competitor.
  • Level 4 (No-Code): Future platforms where you just prompt a GUI without writing code.

3. The Three Types of Agents You Can Build

ADK allows you to create three distinct types of agents depending on what you need them to do:

  1. LLM Agents: (Dynamic & Intelligent) Uses an LLM at its core. Highly flexible. It decides on the fly what to do, what tools to call, and how to plan. It is non-deterministic, meaning it might solve exactly the same problem slightly differently each time.
  2. Workflow Agents: (Structured & Predictable) These do NOT use an LLM for flow control. They are strictly sequential, parallel, or looped pipelines. Highly deterministic. Perfect for compliance tasks (e.g., A refund agent must verify order ID -> check discount -> process refund in that exact order).
  3. Custom Agents: (Highly Tailored) A mix of both. Built by extending the base agent directly for specialized integrations.
The Secret Sauce: Multi-Agent Systems
True power lies in combining these. A Workflow Agent acts as a manager, executing a strict process, but hands off certain dynamic language tasks to an LLM Agent.

4. ADK Components: Deep Dive

To write ADK code, you must understand its components. They are imported directly into your Python scripts.

1. Tools (Hands of the Agent)

You can build Function Tools (standard Python functions), Agent Tools (using a specialized child agent AS a tool for a parent agent), or use Built-in Tools (Google Search, Code Execution, RAG pattern out of the box). You can also easily import CrewAI or LangChain tools.

2. Memory, State & Sessions (The Brain's Context)

Session: Stores the current conversational thread.
State: Stores the specific dynamic data within that interaction.
Memory: Long-term storage accessible across sessions (e.g., remembering your name from a chat you had last week).

3. Evaluation (Testing your Agent)

Traditional Unit testing doesn't work well due to LLM variability. ADK provides robust Eval frameworks (test.json and test.evalset.json) evaluating two things:
1. Trajectory & Tool Use: Did the agent actually use the required tools in the right order? (If it answers correctly but skipped the API call, it hallucinated/guessed).
2. Final Response matching: Assessing the quality and similarity of the final response to the expected dataset.

5. How to Actually Write the Code

Here is exactly how the framework translates into Python imports:

  • Agents: from google.adk.agents import ToolCallingAgent
  • Tools: from google.adk.tools import tool (You just wrap regular functions).
  • Runners: from google.adk.runners import Runner (This manages the execution lifecycle, similar to running a Flask app server).
  • Sessions: from google.adk.sessions import SessionService
  • Memory: from google.adk.memory import InMemory
  • Models: from google.adk.models import GeminiModel (Interfacing via litellm).
  • Planners: from google.adk.planners import BasicPlanner (For task routing).
  • Code Executors: from google.adk.code_executors import PythonCodeExecutor (Crucial for AI coding agents to run scripts in safe bash environments).
  • Evaluators/Events: Used to track agent trajectories and score them.

Production Folder Structure

A real ADK app doesn't sit in one file. It looks like this:

my_adk_project/
├── agent.py (Root sequential agent)
├── memory.py (Long-term memory backend interface)
├── artifacts.py (Loads docs for RAG)
├── prompts.py (System instructions/templates that act as the agent's brain)
├── tools.py (Shared utilities, e.g., file system access)
├── sub_agents/
│ └── ... (Each sub-agent has its own specific agent.py, prompts.py, tools.py)
├── data/ (JSON configs and artifacts)
├── deploy/ (Cloud Run / Vertex AI setup)
└── eval/ (Testing scripts)

6. Business vs Developer Choices

Before coding, choose the right route based on your skill level:

  • No-code / Business Users: Use Agent Space or Conversational Agent (fully managed GUIs).
  • Developers: Use ADK framework or build from scratch and deploy on Vertex AI Agent Engine. You have absolute control.
